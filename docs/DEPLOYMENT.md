# Deploy the fictional public demo

Deployment requires explicit approval. The repository contains configurations only. Both hosts are configured to keep Git pushes from triggering deployments.

## 1. Choose the public frontend origin

Choose one canonical HTTPS Vercel domain, such as the project's production `.vercel.app` address. Set the Vercel project root to `frontend`, Node.js to 24, and use the Vite preset. The build publishes `dist`. The browser only contacts its own origin. Vercel rewrites `/api/*` to Render over HTTPS, and the API's responses use `Cache-Control: no-store`. Alternate frontend domains and preview URLs require a separate backend configuration.

## 2. Prepare Neon

After approval, sign in to Neon and create or select a dedicated **free-tier demo database**. Do not use a database with private invoices. Copy its **direct** connection string from Connect and put it in Render's secret settings only. Replace the scheme with `postgresql+psycopg://` and set `sslmode=verify-full&sslrootcert=system`, preserving other options such as `channel_binding=require` if Neon supplies them. The app uses at most five database connections per worker and uses the direct endpoint for migrations as well as runtime.

## 3. Configure Render and Vercel

After approval, sign in to Render, authorize access to the existing GitHub repository, and apply the root `render.yaml` Blueprint on the Free plan. Confirm plan limits before creating any resources. Supply these values directly in the Render dashboard.

| Render variable | Value |
| --- | --- |
| `INVOICEIQ_PUBLIC_DEMO` | `1`, set in the Blueprint |
| `INVOICEIQ_DEMO_ORIGIN` | Exact canonical Vercel HTTPS origin with no trailing slash |
| `INVOICEIQ_SESSION_SECRET` | Generated by Render. Keep it stable across restarts |
| `DATABASE_URL` | Verified-TLS Neon URL from step 2 |

The Docker image includes English OCR data and starts as a non-root user. It validates the configuration, runs `python -m alembic upgrade head`, and starts a single Uvicorn worker on Render's `PORT`. The health check is `/api/health`. If Render assigns a different hostname, update the API rewrite in `frontend/vercel.json` before manually deploying Vercel. Keep the API rewrite above the SPA fallback. Vercel needs no database or signing secrets.

## 4. Smoke-test before sharing the link

1. Open the approved Vercel URL and check that Overview loads. Confirm `/api/session` sets a host-only, Secure, HttpOnly, SameSite=Strict cookie and that API responses are not cached.
2. Use **Upload → Use sample invoice**, verify **JS-1042** and **USD 129.60**, then save. Find it in Invoices, verify the USD total in Analytics, and submit the sample again to see the duplicate warning.
3. Open the demo in a separate browser profile. Confirm the invoice is absent and its detail URL cannot load it. Delete the test record from the first profile.
4. Check Render health and verify the deployed origin and PostgreSQL connection. On a free-tier cold start, allow the service time to wake.

## Demo boundaries

Sessions are anonymous, signed and expire after 24 hours. Each session can store up to 25 rows. Records older than 24 hours are purged opportunistically on a successful demo save. API and extraction limits are per session and per process. Keep one instance and one worker for this configuration. The API rejects every upload except the exact bundled fictional PDF before parsing it. Use fictional values in the editable form. Local mode retains general PDF, PNG, and JPEG support. Use a separate design and account-based access controls before accepting real financial records.
